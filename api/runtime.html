Runtime

O módulo runtime é responsável por gerenciar o ciclo de vida do SDK de workflow na aplicação consumidora.

Por meio dele, a aplicação pode inicializar o SDK a partir de um arquivo YAML, obter acesso à instância compartilhada do motor de workflow e encerrar sua utilização quando necessário.

Para isso, o módulo disponibiliza funções que centralizam o carregamento, a validação e a inicialização da configuração, garantindo que o motor esteja pronto para ser utilizado pela aplicação.

A seguir, são apresentadas as responsabilidades do módulo e as funções disponibilizadas para integração com a aplicação consumidora.

Gerencia o ciclo de vida do runtime do SDK de workflow.

Este módulo implementa o gerenciamento da instância compartilhada do motor de workflow, permitindo que a aplicação consumidora inicialize, acesse e encerre o runtime por meio de funções públicas.

A instância do motor é mantida durante o ciclo de vida do runtime, evitando inicializações desnecessárias e garantindo que a aplicação utilize a configuração carregada.

Principais responsabilidades:

  • Carregar e validar o arquivo YAML de configuração.

  • Inicializar o motor de workflow.

  • Garantir a inicialização única do runtime.

  • Disponibilizar a instância configurada do motor.

  • Permitir o encerramento do runtime.

  • Registrar logs das operações de inicialização e encerramento.

Funções públicas:

  • configure: Carrega, valida e inicializa o runtime.

  • get_workflow: Retorna a instância configurada do motor.

  • shutdown: Encerra o runtime removendo a referência global ao motor.

class sme_workflow_sdk.runtime.RuntimeContext(caminho, workflow)[código-fonte]

Base: object

Armazena o estado da instância do SDK.

Mantém as informações necessárias para identificar a configuração utilizada e disponibilizar o motor de workflow inicializado.

Variáveis:

  • caminho (Path) – Caminho absoluto do arquivo YAML utilizado na inicialização do runtime.

  • workflow (MotorWorkflow) – Instância do motor de workflow criada a partir da configuração carregada e validada.

Parâmetros:

  • caminho (Path)

  • workflow (MotorWorkflow)

caminho: Path
workflow: MotorWorkflow
sme_workflow_sdk.runtime.configure(caminho)[código-fonte]

Inicializa o runtime do SDK com um arquivo de configuração.

Carrega e valida a configuração do workflow antes de criar o motor. A instância criada é armazenada no contexto global do runtime.

A inicialização é idempotente para o mesmo caminho. Caso o runtime já esteja inicializado com outro caminho, uma exceção será lançada.

Parâmetros:

caminho (str | Path) – Caminho do arquivo YAML de configuração.

Levanta:

  • RuntimeError – Se o runtime já estiver configurado com outro caminho.

  • ArquivoNaoEncontradoError – Se o arquivo não existir ou não for válido.

  • FormatoInvalidoError – Se a extensão ou o conteúdo YAML for inválido.

  • ConfiguracaoInvalidaError – Se o conteúdo carregado não possuir uma estrutura YAML válida.

  • EstadoInvalidoError – Se houver estados ou referências inválidas.

  • AcaoInvalidaError – Se houver ações ou transições inconsistentes.

Tipo de retorno:

None

sme_workflow_sdk.runtime.get_workflow()[código-fonte]

Retorna a instância global do motor de workflow.

Levanta:

RuntimeError – Se o runtime ainda não foi inicializado.

Tipo de retorno:

MotorWorkflow

sme_workflow_sdk.runtime.shutdown()[código-fonte]

Encerra o runtime removendo a referência global ao motor.

Após o encerramento, chamadas a get_workflow() lançarão RuntimeError até que o runtime seja inicializado novamente.

Referências ao motor mantidas externamente não são invalidadas automaticamente.

Tipo de retorno:

None
